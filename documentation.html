01 / OVERVIEW

What is PPSX33?

PPSX33 is an experimental PlayStation 3 full-recompilation project. Its intended path is to analyse a decrypted ELF, translate supported PowerPC PPU code into generated native source, build it for a Windows x86-64 host, and supply guest runtime services.

Translation volume is not compatibility. Correctness also depends on instruction semantics, control flow, imports, system calls, threads, SPU workloads, DMA, graphics commands, shaders and timing.

Recompiler versus emulator

A static recompiler attempts to produce native code ahead of execution. An emulator typically interprets or dynamically translates guest instructions while modelling hardware. PPSX33 pursues static recompilation, while its runtime still models guest-visible services and devices.

Project facts

  • Input: decrypted ELF
  • Host target: Windows x86-64
  • Graphics: Direct3D 11 path under development
  • Stage: experimental
  • Status source: roadmap and test evidence
02 / GETTING STARTED

High-level workflow

Before building

  1. Read the source README and developer guide.
  2. Use the Windows x64 toolchain specified by the current guide.
  3. Clone the repository and follow current build instructions.
  4. Use only decrypted ELF input and data you are legally entitled to access.

First validation pass

  1. Build documented targets and retain output.
  2. Run the smallest available smoke test.
  3. Preserve lift and analysis reports.
  4. Use the documented strict-fault configuration for correctness checks.
  5. Record build identity, flags, logs and outcome.

For exact setup commands, use the canonical developer guide; this wiki avoids inventing commands that may change.

03 / SUBSYSTEMS

What the system has to implement

ELF analysis

Validate segments and metadata, map guest addresses, and identify code and imports.

PPU lifter

Decode PowerPC instructions and emit native source. Semantic and control-flow gaps can invalidate output.

PS3RT and HLE

Guest memory, import dispatch, LV2 services, PRX support and host facilities. API presence does not mean behavioral completeness.

SPU / MFC / DMA

Execution, DMA ordering, tags, atomics, scheduling and SPURS lifecycle.

RSX / GCM

FIFO progression, state tracking, resource handling, shader translation and title-authored rendering.

GUI and packaging

Native build integration, runtime libraries, generated projects and diagnostics.

04 / VALIDATION

Read status labels precisely

Partial / in progress

Some implementation exists, but correctness, coverage or integration remains incomplete.

Blocked

A downstream feature depends on an upstream capability that is not reliable yet.

Diagnostic assist

Assist cmdstreams test the host RSX path. A diagnostic triangle does not prove a game's scene renders.

Strict fault mode

PS3RT_STRICT_FAULT=1 is documented for correctness runs so unknown or sticky guest PCs are not treated as successful recovery.

Consult the current roadmap for exact status and dependencies.

05 / TROUBLESHOOTING

Start with reproducible evidence

Build succeeds but the title does not run.+

Build success validates only that stage. Inspect lift and analysis reports, guest PC traces, unresolved imports and strict-fault output.

The graphics window appears but the scene is blank.+

A window or present event does not prove title rendering. Check FIFO progress, method decoding, resources, shaders and whether the draw came from an assist path.

An unknown or sticky guest PC occurs.+

Keep the strict-fault trace and determine whether the PC belongs to a translated region, import island or unsupported branch path. Do not treat soft recovery as success.

An import resolves but behavior is wrong.+

Resolution only proves dispatch found a handler. Verify calling conventions, return values, side effects, error codes and thread interactions.

Where should a bug report go?+

Open an issue in the PPSX33 repository with environment, build identity, flags and relevant logs. Do not upload copyrighted game content.
