01 / OVERVIEW

What is PPSX33?

PPSX33 is an experimental full-recompilation project aiming to translate supported decrypted ELF guest code into native Windows builds and supply required runtime behavior.

Wikipedia describes game history and details. Only the core repository, tests and documented title runs can establish implementation status.

Keep sources distinct

Game background comes from Wikipedia; technical status comes from PPSX33's own code and evidence.

02 / WORKFLOW

Investigate a title

  1. Search for a game article and review its cited background sources.
  2. Confirm the input is a decrypted ELF that you are legally entitled to use.
  3. Trace the loader, PPU translation, runtime imports and relevant SPU/RSX behavior.
  4. Capture build configuration, logs and the first failure.
  5. Separate compile, launch, menu, rendering, input, audio and sustained gameplay milestones.
03 / RUNTIME

Runtime and HLE

The runtime may need guest-memory mapping, import resolution, LV2 calls, PRX loading, threads and synchronization, files, audio, input and save services.

MemoryGuest addresses, permissions and access faults.
ImportsSymbols/NIDs and explicit unsupported-service behavior.
ThreadsScheduling, waits, events, mutexes and lifecycle.
ServicesFilesystem, audio, controllers and persistent data.

Stubbed calls should be visible in diagnostics. A plausible return value is not the same as correct semantics.

04 / GRAPHICS & SPU

Why a test triangle is not enough

Titles can use SPU workloads, MFC/DMA transfers and RSX/GCM command streams. A reliable path must respect guest commands, resource formats, synchronization, shaders, textures, render targets and presentation.

FIFOGET/PUT progression and command boundaries.
ResourcesTextures, buffers, surfaces and memory formats.
ShadersTitle-authored shader behavior.
SynchronizationDMA completion and CPU/GPU ordering.
05 / VALIDATION

What good evidence looks like

  • Exact source revision and build configuration.
  • Input provenance and confirmation of decrypted ELF.
  • Logs preserving the first failure.
  • Focused unit and regression tests.
  • Title-level observations with repeatable steps and limitations.

Consult the canonical roadmap and core repository.

06 / GLOSSARY

Core terms

ELF
Executable and Linkable Format used as guest input.
Full recompilation
Translating guest machine-code behavior into host-native code.
PPU
Power Processing Unit, the main CPU architecture.
SPU
Synergistic Processing Unit used for specialized parallel workloads.
MFC / DMA
SPU transfer and synchronization mechanisms.
RSX / GCM
Graphics processor and its command interface.
HLE
High-level implementation of system function behavior.
07 / TROUBLESHOOTING

Common questions

Build succeeds but no game appears

Check whether entry code is reached, imports resolve, threads progress and the first strict fault is preserved.

Execution appears stuck

Inspect repeated PCs, branch recovery, wait conditions, thread state and guest progress counters. Do not fake successful returns to bypass a loop.

A window opens but the game does not render

Trace guest FIFO progress, command decoding, resource creation and shader handling. Record diagnostic draws separately.

Does a Wikipedia result mean compatibility?

No. Compatibility requires reproducible PPSX33 title tests and documented outcomes.
