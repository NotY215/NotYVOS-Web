SYSTEM ARCHITECTURE

From firmware handoff to desktop.

The current rewrite uses a small appliance stack: Linux kernel, BusyBox init, a session script, seatd, cage as a kiosk Wayland compositor, and notyvos-xmb built with SDL2. The main repository README and docs/architecture.md are canonical.

01 / KERNEL

CPU, memory and processes

The Linux kernel provides the underlying CPU, memory, device and process services. NotYVOS currently configures a silent boot with no visible console.

CPU platform

Linux kernel and Buildroot provide processor, memory, device and scheduling foundations.

Memory

Kernel memory management is supplied by the Linux kernel; NotYVOS does not currently maintain its own native PMM/VMM implementation.

Processes

The appliance starts a configured session and launches the XMB UI. A general-purpose desktop/user process model is not the current product surface.

02 / STORAGE

VFS, initramfs and NYFS

The current image uses Buildroot's root filesystem. User media is expected under /data/Photo, /data/Music, /data/Video and /data/Game; persistent disk-image packaging is not complete.

VFS

Path lookup, VNodes, per-task FileTable and stable read/write/seek surface.

Initramfs

ustar archive mounted at root for early userland and static assets.

NYFS

NYFS is not part of the current rewrite's active storage design. The project currently relies on the Buildroot root filesystem and has not yet completed persistent disk-image packaging.

03 / GRAPHICS

Graphics API → HAL → compositor

The XMB is rendered by SDL2 on a logical 1920×1080 canvas scaled to the display, with procedural wave geometry and monthly theme colours. TrueType text feeds the compositor via draw_text.

Compositor

Background, taskbar, Start menu, windows, Alt-Tab, snap layouts, toasts and context menus.

TrueType

Inter Regular parser, 4× coverage rasterizer, per-face glyph cache and anti-aliased text.

Decoders

BMP, PNG, GIF, ICO and JPEG feed Image Viewer and the graphics pipeline.

04 / PS3 RUNTIME

A separate compatibility-oriented execution path

PS3 binaries are identified and parsed, then supported PowerPC code can run through the interpreter or the baseline x86-64 JIT. RSX provides a software compatibility path for graphics commands.

PPUPowerPC decoder, interpreter and JIT
SPULocal store and mailbox foundations
DMACell-style queue and synchronization
RSXFIFO, raster, textures, depth and mipmaps
05 / DEVICES

Native drivers and input

Storage & power

Hardware support is supplied by the Linux kernel and Buildroot configuration; current real-hardware compatibility is unverified.

Network & audio

Networking and sound are planned, not currently implemented in the XMB appliance. Production stack is Phase 16.

Input

Keyboard and mouse drive the XMB through SDL2. Native DualShock USB/Bluetooth support is future work.
