SYSTEM ARCHITECTURE

From decrypted ELF to native execution.

PPSX33 is a full-recompilation effort: analyse guest PowerPC code, emit native code, link it with a host runtime, and validate every layer with evidence. This guide describes boundaries, not complete compatibility.

Engineering notes ↗Current roadmap ↗
01 / DATA FLOW

The recompilation pipeline

Each stage has separate correctness requirements and failure modes.

01

Input and analysis

Accept a decrypted ELF, inspect segments and metadata, map guest addresses, and identify code and imports. PPSX33 does not decrypt retail content.

02

PPU lifting

Translate supported PowerPC regions into generated C++. A lift report is not proof of complete instruction semantics or control-flow recovery.

03

Native build and runtime

Build generated sources with the Windows C++ toolchain and connect guest memory, imports, LV2/HLE, PRX, SPU/MFC/DMA and system services.

04

SPU and DMA

SPU execution, MFC operations, DMA ordering and SPURS scheduling must preserve guest-visible behaviour. Coverage remains partial.

05

RSX/GCM graphics

Parse command streams, track graphics state and resources, process shaders, and submit work to Direct3D 11. Assist draws are diagnostic only.

06

Evidence and validation

Use strict-fault runs, traces, tests and per-title records. Do not infer bootability from compilation, lift counts, or a host window.

02 / CONTROL FLOW

Runtime path and failure boundaries

Conceptual system view. Partial or blocked components must not be interpreted as complete.

flowchart TD
  ELF[Decrypted ELF] --> LOAD[ELF loader and guest memory]
  LOAD --> ANA[Analysis and address map]
  ANA --> LIFT[PPU decoder and lifter]
  LIFT --> GEN[Generated C++]
  GEN --> BUILD[Native Windows build]
  BUILD --> RT[PS3RT guest runtime]
  RT --> HLE[LV2 / PRX / NID HLE]
  RT --> SPU[SPU / MFC / DMA]
  RT --> GCM[RSX / GCM command path]
  GCM --> D3D[Direct3D 11 backend]
  HLE --> TEST[Trace and correctness tests]
  SPU --> TEST
  D3D --> TEST
03 / SUBSYSTEM RESPONSIBILITIES

Where correctness lives

Compiler side

ELF parsing, instruction decoding, control-flow recovery, PPU semantics, code emission, generated build integration and analysis reports.

Runtime side

Guest address space, CPU context, import dispatch, system/library behaviour, thread primitives, SPU/MFC/DMA and host services.

Graphics side

FIFO GET/PUT correctness, method decoding, RSX state, shader translation, textures, render targets, depth/blend state and presentation.

Validation side

Strict faults, reproducible builds, smoke tests, conformance tests, title logs and repeatable evidence. Soft recovery is not authoritative success.

04 / SOURCE OF TRUTH

Evidence-led status

The current roadmap prioritizes PPU recovery and semantics, null-loop recovery without invented success, FIFO GET/PUT correctness, guest PUT progress without boot assist, and title-authored draws/shaders. Assist cmdstreams test a host path, not real title rendering.
