PPSX3

An experimental PlayStation 3 static recompiler that translates decrypted ELF64 big-endian PowerPC64 input into host-side C/C++ and build artifacts. It is a recompiler project, not a complete PS3 emulator.

PROJECT SURFACE

What PPSX33 contains

The repository combines ELF analysis, PPU lifting, runtime scaffolding and developer tooling.

ELF

ELF64 analysis

Loads big-endian PowerPC64 ELF segments and analyzes entry points, symbols, function descriptors and embedded SPU images.

PPU

Static PPU lifting

Translates PPU instruction instances to generated host-side code. Some instruction behavior remains approximate and requires semantic tests.

CLI

GUI and CLI workflow

A C/C++ core, command-line frontend and C# WinForms GUI support project setup, lifting, host builds and report inspection.

RT

Guest runtime

Runtime helpers cover guest memory and CPU state. SPU APIs and RSX surfaces remain stubs rather than full execution or rendering implementations.

TEST

Synthetic smoke test

A generated PPC64 ELF exercises the pipeline and expects the test output “OK”. It validates the workflow, not commercial-game compatibility.

U2

Uncharted 2 analysis

Planned as a static-lift and opcode-discovery target to identify missing or approximate PPU operations and add regression tests.

Development priorities

  • Improve PPU semantic correctness and runtime stability using focused synthetic tests and the God of War III analysis target.
  • Use Uncharted 2: Among Thieves to discover additional opcode gaps and prioritize regression-backed implementation work.
  • Develop SPU execution, RSX/GCM rendering and system-library compatibility as separate workstreams.

Build environment

Windows development uses CMake, Ninja, a C++17-capable compiler and the .NET 8 SDK for the GUI. Visual Studio 2022 with the C++ workload and Windows SDK is a documented setup.

scripts\build_all.bat
scripts\run_smoke_test.bat

Build output is placed in build\dist\. See the repository README for Linux/macOS-compatible smoke-test commands and the complete workflow.

HONEST STATUS

Translation coverage is not compatibility

A translated instruction count only says that the lifter emitted output for the analyzed instances. It does not prove the generated behavior matches PowerPC semantics or that a full game works.

Semantic correctness

Approximate operations, incomplete architectural state and no-op fallbacks may still appear as translated instructions.

Runtime correctness

Guest control flow, system calls, imports, memory behavior and runtime services need separate verification.

Game compatibility

Full boot, gameplay and rendering are not established by the current static-lift snapshot.
