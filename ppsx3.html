PPSX33

An experimental PlayStation 3 static recompiler for decrypted ELF64 big-endian PowerPC64 input. The current codebase includes a C/C++ core, CLI, C# WinForms GUI, PPU lifting, experimental SPU/RSX paths, live build progress and cancellation, keyboard/XInput input mapping, early audio and PS3-native save/load HLE, and runtime recovery work. PPSX33 is not a complete PS3 emulator.

Legal notice, privacy and redistribution

The application requires legal acknowledgment before loading an ELF, and the repository provides a first-run Terms screen. Use only files you are authorized to analyze. PPSX33 does not ship proprietary decryption keys, game dumps, decrypted EBOOTs or commercial-game assets. Third-party tools and assets retain their own licenses, and compiler binaries must only be redistributed where their terms permit it. Runtime reports can include local paths, addresses, module strings and other input-derived information, so review logs before sharing.

ELF64 analysis

Loads big-endian PowerPC64 ELF segments, handles entry/function descriptors, discovers symbols and OPD entries when available, detects likely PRX/NID strings, and extracts embedded SPU images.

PPU static lifting

Generates host-side C++ in chunks. Integer, branch, memory, floating-point and VMX paths have broad but uneven coverage. Some operations remain approximate or use fallback behavior.

GUI and CLI workflow

Project creation, ELF/SELF loading, lifting, host compilation, running, report viewing and copying runtime files to a game folder are available through the C# WinForms GUI and native CLI. GUI options include D3D11, D3D10 and experimental Vulkan selection, PPU-thread count, an external RPCS3 path, report/log views and a controller tab that is removed once Build begins. The generated host executable is project-named and PPSX33-branded; runtime files can include ps3rt.dll, guest_image.bin and pad_map.json.

Load ELF and optional EBOOT handling are gated by a legal acknowledgment. Decrypt EBOOT delegates to the RPCS3 executable supplied by the user. The codebase does not ship proprietary game data or decryption keys.

Copy to game folder: the GUI searches the selected game folder for EBOOT.BIN and copies the runtime into the directory containing it, normally PS3_GAME/USRDIR. The current workflow also scans game-folder assets under USRDIR/PS3_GAME; copying files does not establish compatibility.

Build progress, Stop / Cancel and output layout

The current GUI tails output/build_live.log, reads BUILD_TOTAL when present, and counts compile/link/cleanup markers to estimate progress and ETA. The percentage is advisory, not a compiler-certified value; some repository prose still describes object-file timestamp progress, so the GUI source is the more current implementation reference. After a successful build, analysis_report.txt, lift_report.txt and build_log.txt are retained at the project root, while output/ holds the host executable and runtime files such as ps3rt.dll, guest_image.bin and pad_map.json. The successful post-build layout removes generated input/ and codebase/ folders.

Stop / Cancel is context-sensitive: during a build it asks for confirmation and requests native cancellation; the cancelled-build path can remove generated input/, codebase/ and output/ folders and unload the active project, so reload the ELF before continuing. While a game is running, Stop ends that game process. Decompilation is synchronous and is not cancellable by this control. Progress and ETA are estimates, and a successful host build does not prove that a game runs correctly.

SPU runtime foundations

SPU context, local-store handling, loading/execution helpers, mailboxes and MFC/DMA paths exist in the runtime. ISA coverage, vector and floating-point semantics, full channel support and SPURS remain partial and require focused validation.

RSX path

Partial FIFO/method decoding, surface and draw tracking, flip/control handling, clear colour, depth/stencil operations, and D3D11 presentation are present. Phase XIX batches FIFO processing up to 16,384 methods per pass, skips presentation on empty frames (with periodic keep-alive presentation), and batches progress/flush work. This is still not a complete RSX command processor or renderer; D3D10 and experimental Vulkan selection must not be read as complete backend compatibility.

Runtime compatibility and current GOW3 evidence

Guest memory, PPU state, LV2/PRX HLE, GCM, SPU execution, RSX presentation, audio and save-data calls remain experimental. The runtime includes recovery heuristics for invalid/repeated call targets, selected event-queue/GCM fallback behavior, SPU context/mailbox/MFC paths and partial input mapping. These may approximate system behavior or redirect execution.

The two GOW3 logs dated 14 October 2026 show boot/memory mapping completing, the PPU run reaching RUNNING, XInput polling, GCM control/label/FIFO initialization, and D3D11 host presentation at 1280×720. They record 32 flips, one counted draw, three clears, depth/stencil activity and four recognized RSX methods with zero unknown methods in the logged sample. The window was then closed by the user. This is evidence of runtime progress and basic host-window/RSX activity, not proof of actual game-scene rendering, audio, title-screen progress or playability.

Keyboard and controller input

The runtime exposes a guest pad-state setter and the current implementation documents keyboard plus XInput mapping into cellPad. The GUI's controller tab lets users edit keyboard bindings before Build; the tab is then removed and the mapping locked for that build. Defaults include arrow keys for the left stick, H/J/K/U for the right stick, V for Start, Space for Select, Backspace for PS, and letter/numpad/modifier bindings for the remaining controls. End-to-end compatibility still requires title-level validation. Read key mapping details ↗

Audio and save-data foundations

Selected cellAudio/libaudio calls have early host audio HLE plumbing; the Windows path opens 48 kHz stereo waveOut, but the current implementation can queue silence and should not be advertised as working game audio. Save-data HLE uses PS3-native save/load paths under the user's Documents folder. Savestates are explicitly out of scope, and real game save compatibility is not established. Runtime correctness before claims of compatibility

GOW3 is the primary runtime target

The current roadmap records phases I–XIX and package items XX-A–XX-G as done, with XX-H pending for a full playable pass from title screen to in-game UI/assets/audio. The 14 October logs show the runtime reaching RUNNING and exercising GCM/RSX paths, but the recorded activity is limited and the user closed the host window. No log evidence here establishes a successful title screen or playable game.

The six game records remain static-lift snapshots. GTA V records 6,934,214 translated instances across 847 chunks, while San Andreas records 1,893,428 across 232 chunks. Zero reported unimplemented instructions and 100% static translation are not measures of correct semantics, import resolution, startup, rendering or playability. Minecraft, Uncharted 2 and Demon's Souls remain lift/stress targets, not validated runtime targets.

Validate each layer independently

The synthetic smoke test checks the lift/build pipeline with a generated PPC64 ELF. It does not establish commercial-game compatibility. SPU execution, RSX rendering, library behavior and guest operating-system expectations require separate tests.

Use the repository's lift reports and game records for exact per-run details. Commercial ELF files, EBOOT files, keys and proprietary assets are not included in the project repository.

BUILD ENVIRONMENT

Windows development

Current documented setup uses CMake, Ninja, a C++17-capable compiler, the Windows SDK, and .NET 8 for the WinForms GUI. The repository documents Visual Studio 2026 (version 18) with Desktop development with C++ as its development setup. Run scripts/build_all.bat to build the native core, CLI and GUI into build/dist/. The GUI reads output/build_live.log and uses BUILD_TOTAL plus compile/link/cleanup markers for approximate progress/ETA; it is not a compiler-certified percentage. The native build and GUI post-build workflow keep reports and the build log at the project root while output/ holds runtime artifacts. PPSX33 Alpha 01 is a historical experimental Windows x64 snapshot; its package features may lag behind current main and it is not a production compatibility claim.

From a configured developer command prompt, run scripts\\build_all.bat. Build output is placed under build\\dist\\. The GUI target may be skipped when the .NET SDK is unavailable.

For the synthetic pipeline check, use scripts\\run_smoke_test.bat on Windows or bash scripts/run_smoke_test.sh on supported Unix-like environments. Alpha 01 release notes describe the intended package contents and validation checklist; they do not certify that the final archive passed clean-machine testing.
