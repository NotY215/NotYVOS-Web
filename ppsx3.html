PPSX33

An experimental PlayStation 3 static recompiler for decrypted ELF64 big-endian PowerPC64 input. It includes a C/C++ core, CLI, C# WinForms GUI, guest runtime support, PPU lifting, SPU interpreter work and an early RSX compatibility path. PPSX33 is not a complete PS3 emulator.

IMPLEMENTATION STATUS

What is in the codebase

ELF64 analysis

Loads big-endian PowerPC64 ELF segments, handles entry/function descriptors, discovers symbols and OPD entries when available, detects likely PRX/NID strings, and extracts embedded SPU images.

PPU static lifting

Generates host-side C++ in chunks. Integer, branch, memory, floating-point and VMX paths have broad but uneven coverage. Some operations remain approximate or use fallback behavior.

GUI and CLI workflow

Project creation, ELF loading, lifting, build invocation and report viewing are available. Windows output can include game.exe, ps3rt.dll and guest_image.bin.

SPU interpreter

Context and local-store support plus major instruction families, mailboxes and MFC/DMA plumbing exist. Full vector and floating-point semantics, complete channel coverage and SPURS remain partial.

RSX path

FIFO method decoding and a flip/control path are present, with early raster and host presentation work. Complete RSX behavior and production host GPU backends are not established.

Runtime compatibility

Guest memory, PPU state, syscall helpers and selected LV2/PRX stubs are under development. Static translation is ahead of runtime compatibility and semantic validation.

CURRENT PRIORITIES

Runtime correctness before claims of compatibility

GOW3 is the primary runtime target

The recorded GOW3 analysis reaches 100% reported static lift coverage, but runtime startup still encounters unresolved external or null call targets, including the observed 0x39800000 path. Current priorities are PRX/function-pointer resolution, startup HLE coverage and semantic hardening.

Uncharted 2 is a secondary static-lift target for long-tail PPU encodings and its seven extracted SPU images. Its documented workflow is lift and inspect only; do not treat it as a validated native build target.

Validate each layer independently

The synthetic smoke test checks the lift/build pipeline with a generated PPC64 ELF. It does not establish commercial-game compatibility. SPU execution, RSX rendering, library behavior and guest operating-system expectations require separate tests.

Use the repository's lift reports and game records for exact per-run details. Commercial ELF files, EBOOT files, keys and proprietary assets are not included in the project repository.

BUILD ENVIRONMENT

Windows development

Current documented setup uses CMake, Ninja, a C++17-capable compiler and .NET 8 for the GUI. Visual Studio 2022 with Desktop development with C++ and a Windows SDK is a supported setup.

From a configured developer command prompt, run scripts\\build_all.bat. Build output is placed under build\\dist\\. The GUI target may be skipped when the .NET SDK is unavailable.

For the synthetic pipeline check, use scripts\\run_smoke_test.bat on Windows or bash scripts/run_smoke_test.sh on supported Unix-like environments.
